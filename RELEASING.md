# LLM Reflect release validation

The maintained project is [wallentx/llm-reflect](https://github.com/wallentx/llm-reflect).
`dev` contains the provider adapters; `main` is reserved for upstream synchronization.
Keep the current branch when preparing a release and review all changes before
committing or publishing.

## Versions and package generation

The upstream version in `.claude-plugin/plugin.json` is the base for generated
marketplace packages. The Codex builder adds a deterministic content suffix; the
Claude builder includes its provider-specific metadata and hook content in its
suffix. Regeneration changes cache identities when package content changes.

Do not hand-edit versions or other files in `plugins/codex-reflect/` or
`plugins/claude-reflect/`. A repository rename changes repository metadata and
links; existing plugin IDs and state paths remain compatible.

## Validate before publishing

```sh
python3 tools/build_codex.py
python3 tools/build_providers.py
uv run --no-project --with pytest python -m pytest tests -q
python3 tools/build_codex.py --check
python3 tools/build_providers.py --check
git diff --check
claude plugin validate plugins/claude-reflect
```

Review the maintained source, generated packages, and documentation together.
The README has no fixed version or test-count badge to update. Historical
upstream releases remain in [CHANGELOG.md](CHANGELOG.md).

Smoke-test `install.sh` and the selected marketplace installs in isolated profiles.
Verify repeated setup preserves unrelated settings and removal retains queues.
CI checks generated bytes and tests Linux, macOS, and Windows with Python 3.8/3.11;
actual provider hook execution still needs runtime validation when adapters change.

The repository currently distributes checkout installers and generated marketplace
packages. No additional archive publishing workflow is implied by these checks.
After reviewed changes are published to `dev`, the installation commands in
[README.md](README.md) and [PROVIDERS.md](PROVIDERS.md) use that source.
